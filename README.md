# LED Controller

اپ فارسی Android برای کنترل امن چهار خروجی ESP32 از طریق Bluetooth Low Energy. حداقل نسخه Android، نسخه 6 (API 23) است.

## ساخت اپ Android

پیش‌نیازها:

- Android Studio با JDK 17
- Android SDK 35
- یک گوشی واقعی دارای BLE برای آزمون اتصال

پوشه پروژه را در Android Studio باز کنید، اجازه دهید Gradle Sync انجام شود و سپس variant نوع `debug` را روی گوشی اجرا کنید. برای Android 6 تا 11 مجوز Location صرفاً به‌علت الزام سیستم برای BLE scan درخواست می‌شود؛ اپ هیچ داده مکانی جمع‌آوری نمی‌کند.

> این مخزن Gradle Wrapper باینری ندارد. Android Studio می‌تواند پروژه را با Gradle سازگار sync کند؛ برای CI یک بار دستور `gradle wrapper --gradle-version 8.9` را در محیط دارای Gradle اجرا و فایل‌های wrapper را commit کنید.

## آماده‌سازی ESP32

1. Arduino IDE و پکیج `esp32 by Espressif Systems` نسخه **3.0.7** را نصب کنید.
2. فایل `firmware/led_controller/led_controller.ino` را باز کنید.
3. مقدار `DEVICE_PASSKEY` را برای هر برد به یک عدد شش‌رقمی غیرتکراری تغییر دهید و آن را روی برچسب دستگاه ثبت کنید.
4. در صورت نیاز `DEVICE_NAME` و آرایه `LED_PINS` را تغییر دهید.
5. Board و Port مناسب را انتخاب و sketch را Upload کنید.

اتصال پیشنهادی هر خروجی:

```text
GPIO 16/17/18/19 ---- مقاومت 220 تا 1000 اهم ---- آند LED
GND -------------------------------------------- کاتد LED
```

پایه‌ها برای ESP32 کلاسیک انتخاب شده‌اند. پیش از استفاده از ESP32-C3/S3، شماره GPIOهای قابل استفاده برد خود را بررسی و آرایه `LED_PINS` را اصلاح کنید.

برای پاک‌کردن Bondهای ذخیره‌شده، دکمه BOOT (GPIO0) را هنگام روشن‌کردن برد حداقل پنج ثانیه نگه دارید. سپس Bond قبلی را از تنظیمات Bluetooth گوشی نیز حذف کنید.

## قرارداد BLE نسخه ۱

| مورد | UUID / مقدار |
|---|---|
| Service | `7e57d004-2b97-4db4-b160-5d8f9d7a1000` |
| ProtocolInfo (Read) | `...1001`، دو بایت: نسخه `1` و قابلیت‌ها `0x0F` |
| Control (Write With Response) | `...1002`، یک بایت bitmask مطلوب |
| State (Read + Notify) | `...1003`، یک بایت bitmask واقعی GPIO |

Characteristicها تنها پس از Secure Connections pairing همراه با MITM و Bonding قابل استفاده‌اند. تغییر ناسازگار پروتکل باید Service UUID جدید داشته باشد.

## چک‌لیست آزمون سخت‌افزاری

- ورود با اثر انگشت و PIN/الگو/رمز روی Android 6، 8، 10، 11، 12 و یک نسخه جدید بررسی شود.
- رد مجوز، خاموش‌بودن Bluetooth، نبود برد و پایان مهلت اسکن بررسی شود.
- passkey درست و غلط، حذف Bond از هر سمت و factory reset برد بررسی شود.
- هر چهار LED جداگانه و در ترکیب‌های مختلف با وضعیت اپ تطبیق داده شوند.
- لمس سریع چند سوییچ، قطع برق برد وسط فرمان و reconnect آزمایش شود.
- خروج اپ به پس‌زمینه باید اتصال را قطع و اپ را قفل کند.
- برای عیب‌یابی، در Developer options گوشی Bluetooth HCI snoop log و در Arduino IDE سریال مانیتور 115200 فعال شود؛ پس از آزمون HCI logging خاموش شود.

## حریم خصوصی و محدوده

اپ شبکه یا analytics ندارد. فقط آدرس عمومی BLE برد انتخاب‌شده در DataStore ذخیره می‌شود؛ رمز گوشی، داده بیومتریک، passkey و کلیدهای Bond داخل اپ ذخیره نمی‌شوند. نسخه اول فقط یک برد و چهار خروجی را پشتیبانی می‌کند.
